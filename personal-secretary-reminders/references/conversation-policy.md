# 对话与确认策略

## 目标

让用户像给私人秘书发消息一样低成本表达，同时避免“记错了却准时提醒”的高信任损失。追问不是收集所有可能字段，而是消除会改变分类、执行或提醒的歧义。

所有用户可见回复同时遵守 `wechat-output-style.md`：结论先行、纯文本分组、禁止 Markdown 表格、原始 JSON、emoji、颜文字和装饰性图标符号。除非用户在当前请求中明确要求，否则不例外。

Agent 自行撰写的追问、确认或错误说明必须先经 `sanitize-output`；脚本已经返回 `wechat_text` 时直接发送，不再添加开场、表情或装饰。

## 分类决策

1. 必须在某个时刻发生，错过即失效：`event`。
2. 有一个可验证结果和一个下一步：`task`。
3. 需要两个以上动作或跨多天推进：`project`。
4. 当前不承诺执行但要在某日重新决定：`someday`。
5. 只有想法、没有行动承诺：`idea`。
6. 下一步取决于他人：`waiting`，有明确接手人时同时填 `delegated_to`。
7. 仅供查阅、不需行动：`reference`。

用户一句话可能包含多个事项。拆分前先复述边界，分别生成草稿，避免把“开会并把纪要发给团队”误存为单个 event。

## 最小追问原则

- 一次优先问 1–2 个最高信息增益问题。
- 用户已经给出的字段不重复问。
- 15 分钟以内的短电话、取件等不问预计用时；会议或复杂任务必须问。
- “月底”“下周”等能安全解析时展示具体日期让用户确认；存在多个合理解释时追问。
- 无截止时间的 task 必须问它是否其实是 someday；不要擅造截止日。
- 灵感不问重要性、截止和提醒。
- 地点、对象、精力、依赖只在会影响“何时能做/能否做”时问。

## 完成定义与下一步

把模糊词改写为可观察结果：

- “做报告” → “形成可供经理审核的季度报告初稿”。
- “处理保险” → 项目“完成家庭保单盘点并形成续保决策”，下一步“收集所有现有保单”。
- “跟进小王” → “向小王询问数据交付时间”，若已询问则转 waiting 并设置复查日。

不要替用户虚构结果。可以给一条建议版本，等待用户确认。

## 确认卡模板

```text
准备这样记录：
类型：复杂待办
事项：完成季度报告初稿
完成标准：可供经理审核
下一步：列出报告大纲
截止：7月31日 17:30
预计：120分钟；系统按150分钟反推 start-by
重要性：5/5；当前 P2
提醒：start-by、前一天进度检查、截止日
静默穿透：否
确认保存吗？
```

省略与该类型无关的行。用户说“好的/确认/就这样”后才 finalize；含有修改内容的“好，不过改到周五”先 clarify 并重新展示卡。

## 快捷回复语义

- “收到/知道了”：ack，只取消 P1 唯一跟进。
- “完成/做完了”：complete；复杂任务可顺势问实际用时。
- “延期到……”：update + reschedule，重新计算 start-by、优先级和提醒。
- “稍后/半小时后再叫我”：snooze。
- “取消这件事”：cancel；若用户说的是“取消提醒但保留任务”，只管理 reminders，不取消 item，并明确区分。

## 时间范围查询语义

- “这周/本周/这个星期还有啥事”“这周剩什么”统一调用 `agenda week`，默认 `scope=remaining`。
- “这个月/本月还有什么”“帮我梳理一下这个月”统一调用 `agenda month`，默认 `scope=remaining`。
- “把本周全部展开”“完整列出来”重跑 agenda 并传 `section_limit=20`，不要仅基于上一次被截断的文字续写。
- “复盘本周”“这一周发生过什么”才使用 `scope=full` 或 `digest weekly`；不要把已经结束的日程混入“还有什么”。
- “周报/月报”包含行为回顾、项目健康、灵感与规则建议；“本周/本月还有什么”只回答剩余事项和当前风险。两者不得混淆。
- 期间边界只采用脚本按设置时区计算的 `period_start`、`period_end`，不要由模型口算。

## 不确定与失败

- 不能确定指的是哪条事项时，列出最多 3 个候选让用户选。
- cron 创建失败时明确说“事项已保存，但提醒未生效”，不要用模糊成功话术。
- cron 缺少明确 delivery 目标或使用 `last` 时视为创建失败；isolated 是执行上下文，不等于投递失败。本 Skill 的新提醒仍优先使用确定性 command job。
- 数据库写入失败时不得继续创建 cron，避免出现孤儿提醒。
- 发现 `sync_error` 时优先修复或告知，禁止静默创建重复提醒。
- OpenClaw Gateway 不可达或云服务器离线时说明不能实际投递；Cron 持久化不等于离线仍能发微信。
