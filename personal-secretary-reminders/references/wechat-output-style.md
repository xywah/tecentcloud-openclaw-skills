# 微信纯文本短报规范

## 目标

让每条回复在微信手机端准确、完整、易扫读。采用咨询式表达原则：结论先行、同类归组、重点有限、依据透明、下一步明确。不要模仿咨询公司的术语或腔调；只保留其清晰结构。

## 强制格式

1. 第一行使用 `【主题｜时间范围】`；不需要时间范围时使用 `【主题】`。
2. 第二行以 `结论：` 开始，先回答用户真正问的问题，再给数量和风险。
3. 后续只使用短标题和数字编号，例如 `【优先待办】`、`1. ...`。
4. 每项控制在一到两行。第一行写事项、优先级和时间；第二行只写最关键的一个或两个排序依据。
5. 默认最多突出 3 个重点。需要完整梳理时按“待办、硬日程、项目、等待与复查”分类，不混在同一列表。
6. 没有结果时明确写“没有已记录的未完成事项”，不要用空标题或含糊表达。
7. 内容过长时先给准确总数，每个分组展示有限条目，最后说明剩余数量和展开指令。

## 禁止项

- 不使用 Markdown 表格，也不使用 `|` 或连续空格模拟表格。
- 不使用代码块、HTML、引用块或三级以上嵌套。
- 不发送原始 JSON、内部 ID、数据库字段、脚本路径、工具调用过程或推理过程。
- 不用大量 emoji 装饰；普通回复默认不用 emoji。
- 不堆叠“好的、收到、没问题”等开场，直接给结果。
- 不把“收到”说成“完成”，不把“已保存”说成“提醒已生效”。
- 不用伪精确结论，例如“成功率 87%”。排序分数只作为内部比较，用户侧说明原因。

## 固定模板

### 保存前确认

```text
【待确认事项】
结论：我准备把它记录为复杂待办；确认后才会正式保存并创建提醒。

1. 事项：完成季度报告初稿
2. 完成标准：形成可供经理审核的版本
3. 下一步：列出报告大纲
4. 截止：7月31日 17:30
5. 预计用时：120分钟；建议最迟7月31日 15:00开始
6. 优先级：P2；重要性5/5
7. 提醒：最迟开始、前一天检查、截止时

请回复“确认”，或直接告诉我要改哪一项。
```

### 保存成功

```text
【已记录】
结论：事项已保存，3个提醒均已生效。

1. 完成季度报告初稿
2. 截止：7月31日 17:30
3. 最迟开始：7月31日 15:00
```

若 cron 未全部成功，把结论改为：`事项已保存，但提醒尚未生效。` 随后只给一个明确修复动作。

### 本周或本月事项

优先直接发送 `agenda` 返回的 `wechat_text`。不得把 `tasks`、`events` 等 JSON 数组自行转换成表格。

### 现在做什么

优先直接发送 `plan-now` 返回的 `wechat_text`。最多给 3 项，第一项必须是明确建议，不把选择重新丢给用户。

### 失败

```text
【提醒未生效】
结论：事项已经保存，但微信提醒创建失败；当前不会按时推送。

下一步：我会保留事项记录。请先恢复 Gateway 或微信连接，再让我执行“修复提醒”。
```

## 发送前检查

发送任何用户可见内容前逐项检查：

1. 第一屏能否直接看到结论？
2. 是否准确回答了用户问的时间范围？
3. 是否存在 Markdown 表格、竖线、代码块或原始 JSON？如有，重写。
4. 数量、时间、状态是否来自脚本返回，而不是凭印象补全？
5. 是否把逾期、已过 start-by、同步异常明确标出？
6. 是否有重复事项出现在多个分组？如有，只保留在最重要的分组。
7. 是否给出了清晰下一步或展开方式？
